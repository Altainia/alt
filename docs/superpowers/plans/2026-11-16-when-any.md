# `alt::when_any` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `alt::when_any`, which races several awaitables, yields the winner's position and value, stops the losers, and does not return until every child has retired.

**Architecture:** A sibling of `alt::when_all` built on the same refcounted shared block, fan-out, per-child cancellation roots and completion counter. What is new is an election: each child's wrapper compare-exchanges its own position into an atomic winner, the winner alone writes its slot and asks the block to stop the others, and the awaiting chain stays parked on the counter until the last of them retires. The result is a named type over a variant rather than a bare `std::variant`.

**Tech Stack:** C++23, header-only, GoogleTest, CMake presets.

**Spec:** `docs/superpowers/specs/2026-11-15-when-any-design.md` — this is PR 2 of its two-PR staging. PR 1 (`SameMinorVersion`'s predecessor, the liveness guard) is merged; `main` is at `d42f3ba`, version **1.11.1**.

## Global Constraints

- C++23; GCC 13+ or Clang 19+.
- `snake_case` throughout; `PascalCase` template typenames; `m_` on private and protected members; `const` by default; Doxygen `/** */` on every public symbol, updated when a symbol's meaning changes.
- American spelling, except the approved `cancelled`/`cancellable`/`cancellation` forms.
- `tests/.clang-tidy` is appended to, never rewritten. A new death test needs its own `NOLINTNEXTLINE(readability-function-cognitive-complexity)`; `tests/test_waiter_list.cpp` carries the measured justification for why.
- **Every task runs all eight CI gates before its commit**: GCC debug, Clang-19 debug, `release-tests`, ASan+UBSan, TSan, the whole-project `clang-tidy` gate pinned to `/usr/bin/clang-tidy-19` with `clang-19`/`clang++-19` and `CMAKE_BUILD_TYPE=Debug`, cppcheck, and Coverage with its `coverage` target. The suite is **769 tests** at `main`.
- **Delete each test binary and confirm its md5 changed before believing any `ctest` output.** This project has had three stale-binary incidents across three agents. Grep for `tests passed|tests failed`; do not tail.
- **A mutation measurement records pass, fail and hang separately.** Wrap each repeat in `timeout -s KILL`; `timeout(1)` exits **124** when it kills the child, not 137.
- **Do not weaken an assertion to stabilize a test.** Six assertions that could not fail have shipped here. If a race test needs a guarantee, arrange it with a handshake and assert an equality — `satisfier_handshake` in `tests/test_when_all.cpp` is the worked example, including why a lower bound over a sampled race is the wrong instrument.
- Work reaches `main` through a pull request; `main` is never pushed to directly.

## Review Focus

Five failure modes the spec implies that no happy path exercises, most likely first. Each has its test named in the owning task.

1. **Two children completing concurrently.** Exactly one must win, and the loser's result must be discarded rather than overwriting the winner's slot. Task 2 tests the election alone; Task 5 tests it through a real race.
2. **Cancellation arriving after a winner was elected.** Decision 2 requires `operation_canceled` and the winner discarded. The window is wide — the chain stays parked while the losers unwind — so this is ordinary, not exotic. Task 5.
3. **An empty range.** A race with no entrants can never complete; parking forever is the worst available answer. Task 4.
4. **Every child already complete before the fan-out ends.** The counter can reach zero before the chain parks, so the join must refuse rather than resume nobody — the path stage A's starter count exists for. Task 3.
5. **A winner that throws while losers are still running.** The exception is rethrown at the await (decision 5), but only after the losers retire (decision 4), so the rethrow and the teardown must not race. Task 5.

class combinator_election
{
public:
    static constexpr std::size_t no_winner = static_cast<std::size_t>(-1);

- [ ] **Step 1: Decide decision 8 deliberately, and write the finding down first**

The spec requires this before any second joiner could park on a counter, and it must be settled in writing before the awaiter exists, not after a gate fails.

**`when_any` as specified parks exactly one joiner** — the awaiting chain, on the block's counter, exactly as `when_all` does. The children park on their own awaitables, and `request_children_stop()` parks nobody. So the first of decision 8's three options holds by construction and `claim`'s assert keeps the position PR 1 pinned it at.

Verify that against the code rather than taking this plan's word, and record it in `when_any.hpp`'s class note with the condition that would break it: any later change that parks a second joiner on one counter re-opens all three options, and `WaiterListDeathTest.AClaimThatWouldLoseTheElectionOnADestroyedListAborts` is what would then abort on a benign race. If the verification finds a second joiner, **stop and report** — that is a spec-level decision, not an implementation detail.

- [ ] **Step 3: Run them to verify they fail**

Run: `ctest --preset debug -R WhenAny --output-on-failure`
Expected: FAIL — the header does not exist.

- [ ] **Step 4: Implement the state and the child wrapper**

`when_any_state<Slots>` holds the slots, the `combinator_state`, and the `combinator_election`, with the same `destroy`-function shape `when_all_state` uses. **Declare the block after the slots**, as `when_all_state` does and for the reason its DELICATE note gives.

The child wrapper takes its own position, a pointer to the election, and a pointer to its slot. After its `co_await` returns it elects; **only a winner writes its slot**, and a winner then calls `request_children_stop()`. Resolving the spec's open question: the loser skips the write, because a loser's value is discarded either way (decision 6) and writing it would mean two children storing into slots whose reads are decided by an index that is already settled.

A winner that completes by throwing stores the exception in its slot and still wins (decision 5).

- [ ] **Step 5: Implement `await_suspend` and `await_resume`**

`await_ready()` is unconditionally false, as stage A's is and for the same reason — the block is allocated and the children started in `await_suspend`, the only place with the awaiting handle.

`await_suspend` follows stage A's order exactly, which is load-bearing and documented there: allocate the state, wire the completion hook, `link` the chain's token, take the children's token from the block, fan out, retire the starter, then park on the counter. Do not invent a new order; cite stage A's note.

`await_resume` returns `std::expected<Result, std::error_code>`:

```cpp
[[nodiscard]] std::expected<Result, std::error_code> await_resume();
```

The verdict order is the decision this step exists for. Test `cancelled()` **first**: decision 2 requires a cancellation arriving after a winner was elected to report `operation_canceled` and discard the winner, so the flag outranks the election. Then, with a winner, rethrow its stored exception if it holds one, else build the result from the winner's slot and its index.
